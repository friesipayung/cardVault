# cardVault — Plan Awal

## Tujuan
Aplikasi manajemen kartu loyalty: simpan kartu loyalty (barcode/QR) dari provider preset
atau custom, scan kartu (nomor/nama/identifier), dan dukungan NFC (scan simpan → simulasi
saat dipakai).

## Stack
- Desktop/Mobile shell: Wails v3 (Go) — mendukung Android/iOS via overlay generator.
- Frontend: SvelteKit + Svelte 5 (adapter-static → dist).
- Backend: Go (services bound ke frontend).
- Database: SQLite (modernc.org/sqlite, pure Go, mobile-friendly) — file tunggal.

## Platform
- Desktop: Linux/macOS/Windows (Wails webview).
- Mobile: Android & iOS via `wails3 android/ios overlay:gen` + project native.

## Fitur
1. Kartu loyalty vault
   - Tambah dari preset provider (tinggal nomor/nama/identifier).
   - Tambah manual/custom provider.
   - Tampilkan barcode/QR dari nilai tersimpan.
   - Cari/filter kartu.
2. NFC
   - Scan NFC card → simpan UID/ATQA/SAK/NDEF/raw dump.
   - Tautkan capture ke kartu loyalty.
   - Simulasi NFC card saat dipakai (Android HCE; iOS terbatas — lihat catatan).
3. Provider preset
   - Seed daftar provider populer (Starbucks, IKEA, dll).
   - CRUD provider.

## NFC — Catatan Platform
- Android: gunakan Host Card Emulation (HCE) untuk simulasi. Implementasi native (Kotlin)
  di overlay Android; Go side hanya simpan data.
- iOS: CoreNFC read supported (iPhone 7+); emulasi kartu terbatas (Apple Pay domain).
  Untuk simulasi, mungkin perlu Shortcuts/automation atau device eksternal. Dokumentasikan
  sebagai limitasi.
- Desktop: NFC reader USB (PC/SC) opsional; simulasi hanya tampilkan UID.

## Roadmap (fase)
1. Fase 1 — Scaffold (DONE): Wails + SvelteKit + Go + SQLite + CRUD kartu/provider.
2. Fase 2 — Barcode/QR render di UI + scan kamera (html5-qrcode).
3. Fase 3 — NFC read/simpan (mobile overlay).
4. Fase 4 — NFC simulate (HCE Android).
5. Fase 5 — Sync/backup (export/import SQLite, cloud opsional).
